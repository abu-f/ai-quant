# 公开行情（腾讯 + 新浪，免 Key）

`name: public_cn`，数据全部来自公开行情接口，**不需要任何 API Key**，因此也没有档位限制。

## 覆盖能力

| 数据集 | 来源 | 口径与限制 |
| --- | --- | --- |
| `daily` 日K | 腾讯 `fqkline` | **不复权**原始价；单标的单次最多 800 根（约 3 年）；成交量为手；无成交额（返回 `None`，不造数） |
| `minute` 分钟K | 新浪 `getKLineData` | 支持 1/5/15/30/60 分钟；单标的单次最多 1023 根（1 分钟约 4 个交易日）；成交额可用 |
| `realtime` 实时快照 | 腾讯 `qt.gtimg.cn` | 全市场 5578 只，一轮约 4~6 秒，**内存缓存 20 秒**；含 OHLC、昨收、量额、换手 |

另外实现了两个可选协议方法：

- `get_realtime_symbols(symbols)`：自选/详情按码补拉，不读缓存，延迟低（<1s）。
- `get_realtime_indices(symbols)`：指数行情（`sh000001` 等）同样走批量报价。

`get_instruments("stock")` 从新浪 `Market_Center` 拉全市场维表（约 20 秒），
每天首次调用时后台预热并缓存 12 小时。ETF / 指数维表不提供，由内置源处理。

## 已知缺口（有意不做，避免"看起来对其实错"）

- **除权因子**：公开接口能取到前复权与不复权两套价格，但因子口径（交易所公式 vs
  等比换算）与本地 enriched 管道的期望没有校核过，硬算会静默污染复权链。
  因此不声明 `adj_factor`，跨分红日的图表会出现价格跳空。
- **财务数据**：东财 `datacenter` 接口可得，但五张表的字段契约未逐项验证，暂不声明。
- **五档盘口 / 全量分钟**：需要逐标的轮询或流式端点，公开接口没有稳定批量能力。

## 稳定性说明

公开接口有间歇性限流：东财 `clist` 实测会整段拒连（`RemoteProtocolError`），
因此本插件**完全避开东财**，只依赖腾讯与新浪。

腾讯 K 线有两个域名，行为并不一致，实测（2026-11）：

| 域名 | 结果 |
| --- | --- |
| `web.ifzq.gtimg.cn/appstock/app/fqkline/get` | 200，返回 `day` / `qfqday` 节点 |
| `ifzq.gtimg.cn/appstock/app/fqkline/get` | **501**，正文是跳转 `waf.tencent.com/501page.html` 的 HTML |

带不带 `Referer: https://gu.qq.com/` 与浏览器 UA 会影响判定，因此日K按
`web.` → 裸域名 → 新浪 `scale=240` 三级回退（`client.fetch_daily`）。
回退到新浪时成交量为「股」，已 /100 换成「手」；新浪日线没有成交额字段，
`amount` 返回 `None` 而不是补 0。

> 教训：日K最初固定走裸域名，表现为**接口 200 但 `rows` 为空**，前端显示
> 「待行情」。任何一次域名策略调整都可能让图表整片空窗，所以必须有回退链，
> 且失败要在日志里留下具体域名与状态码。
